MAC STUDIO SETUP: the model and the meter, nothing else

1. Accounts
   - Your own admin account, used only for setup and updates.
   - A standard (not admin) account named "meter":
       System Settings > Users & Groups > Add User... > Standard, name "meter".
   - There is no account for the agent.

2. Close every other door
   - Wi-Fi off. Bluetooth off.
   - System Settings > General > Sharing: everything off (File Sharing, Screen Sharing,
     Remote Login, Remote Management, Media Sharing, AirPlay Receiver).
   - The Mac has one network cable: to the agent box. It has no internet in normal use.
     For updates, follow step 9: the firewall blocks them while it is on.

3. The link to the agent box
   System Settings > Network > the Ethernet port wired to the agent box >
   Details > TCP/IP: Configure IPv4 Manually, IP 10.77.0.1, Subnet 255.255.255.0, no router.
   Find that port's name (en0, en1...):  networksetup -listallhardwareports

4. Model runtime (llama.cpp)
   brew install llama.cpp          (needs Homebrew: https://brew.sh, while on the internet)
   Put the model file (.gguf) in /Users/meter/models/ and set its name in
   org.sandtable.model.plist. Choose a model that supports tool calls.
   Check that it gives word probabilities (run as meter, with the model started):
     curl -s 127.0.0.1:8081/v1/chat/completions -H 'Content-Type: application/json' \
       -d '{"messages":[{"role":"user","content":"Say hi"}],"logprobs":true,"top_logprobs":10}' \
       | python3 -m json.tool | grep -c top_logprobs
   A number above 0 means it works. If it prints 0, update llama.cpp.

5. Meter
   Install pyserial into a fixed folder the meter's start-up file points to (as meter):
     mkdir -p /Users/meter/lib
     /usr/bin/python3 -m pip install --target /Users/meter/lib pyserial
   Check it is found the way it will be at boot:
     PYTHONPATH=/Users/meter/lib /usr/bin/python3 -c "import serial; print('ok')"
   Copy meter.py to /Users/meter/meter.py
   Plug in the USB-serial adapter (receive wire already cut) and find its name:
     ls /dev/cu.usbserial*
   Put that name in org.sandtable.meter.plist.

6. Start both at boot, as the meter's user
   sudo cp org.sandtable.model.plist org.sandtable.meter.plist /Library/LaunchDaemons/
   sudo chown root:wheel /Library/LaunchDaemons/org.sandtable.*.plist
   sudo launchctl bootstrap system /Library/LaunchDaemons/org.sandtable.model.plist
   sudo launchctl bootstrap system /Library/LaunchDaemons/org.sandtable.meter.plist

7. Firewall
   Set LINK in pf-sandtable.conf to the port from step 3, then:
     sudo cp pf-sandtable.conf /etc/pf.anchors/sandtable
     sudo pfctl -nf /etc/pf.anchors/sandtable        (checks it; prints nothing if fine)
   To load it at every boot, add these two lines to the end of /etc/pf.conf:
     anchor "sandtable"
     load anchor "sandtable" from "/etc/pf.anchors/sandtable"
   then: sudo pfctl -ef /etc/pf.conf
   macOS updates sometimes replace /etc/pf.conf: check it after each update.

8. Check from the agent box (after its setup)
     curl -s 10.77.0.1:8080/v1/models         -> works
     curl -s 10.77.0.1:8081/health            -> must fail (the model itself is unreachable)
     ssh 10.77.0.1                            -> must fail

9. Updates (macOS, llama.cpp, the model)
   The firewall blocks everything except the agent box's one port, updates included.
   So the agent box is never connected while the firewall is off:
     a. Unplug the agent box's cable from the Mac.
     b. Switch the firewall off:  sudo pfctl -d
     c. Plug the Mac into your router, update (Software Update; brew upgrade llama.cpp), unplug.
     d. Check /etc/pf.conf still ends with the two sandtable lines from step 7 (updates can
        replace it), then switch the firewall back on:  sudo pfctl -ef /etc/pf.conf
     e. Check it is on:  sudo pfctl -s info | head -1   -> "Status: Enabled"
     f. Plug the agent box back in, and run the checks in step 8.
